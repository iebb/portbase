# PortSQL database client

## Version 1.3.0

The ten improvements below are implemented and validated. Version 1.3.0, build 1 was submitted to App Review on 2026-09-22 and independently verified as **Waiting for Review**.

PortSQL targets iOS 18 and later on iPhone and iPad. Its interaction model follows [DataGrip’s database explorer](https://www.jetbrains.com/help/datagrip/database-explorer.html), [query consoles](https://www.jetbrains.com/help/datagrip/query-consoles.html), and [data editor](https://www.jetbrains.com/help/datagrip/data-editor-and-viewer.html): select a connection and database, browse objects, run queries, and inspect or edit data. Controls use compact labels, without marketing banners or decorative descriptions.

## The ten improvements

1. **Saved-work retention and recovery.** Saved queries and charts no longer disappear when the library reaches 40 queries or 50 charts. Deleted items move to Trash, with Restore and explicit permanent deletion. Library Storage shows saved-item counts, chart-preview storage, history cleanup, and recently closed consoles. Local workspace writes retain a backup and preserve damaged files when recovering. Query history remains a rolling list of 60 executions; saved queries are separate from history. Recovery cannot recreate items already discarded by an older version without a surviving backup.
2. **Multiple query consoles with autosave.** Each console owns its connection, database, SQL or MongoDB draft, cursor, parameters, execution state, and in-memory results. Console drafts are saved locally, restored after reopening, and recoverable from Recently Closed Consoles. Result sets and live database sessions are not restored after app termination.
3. **SQL assistance and execution.** Completion includes aliases, CTEs, quoted identifiers, and functions alongside schema suggestions. Run executes a selection or the statement at the cursor; Run All executes the buffer. PostgreSQL error positions and MySQL error lines are highlighted when supplied by the server. Formatting, Explain, Find and Replace, undo/redo, indentation, and keyboard shortcuts remain available.
4. **Result-grid controls.** Columns can be resized, pinned, and hidden. Cell ranges can be selected and copied, with per-result column settings retained. Row inspection remains available. Explorer sorting and the existing protected row editor continue to use explicit table provenance and typed values.
5. **Persistent SQL sessions and transactions.** A console retains its SQL connection between executions, allowing temporary tables and session settings. Manual-commit mode exposes Commit and Rollback. The service owns transaction state and rejects raw transaction-control statements that could desynchronize it. MySQL statements that can implicitly commit are restricted in manual-commit mode. Closing a console, changing its connection, cancellation, timeout, or app backgrounding closes its session; pending transactions are not silently committed.
6. **Expanded schema explorer.** Browse tables, views, PostgreSQL materialized views, functions, procedures, indexes, constraints, and foreign keys. Inspect definitions and follow foreign-key values to related rows through read-only queries. MySQL definitions come from SHOW CREATE. PostgreSQL views and routines use server definition functions; table definitions are assembled from catalog metadata, with constraints and indexes shown separately. These table previews are not a replacement for a complete schema dump or migration tool.
7. **MongoDB document editing.** Insert, edit, duplicate, or delete documents with typed BSON fields or Extended JSON. Review the original document, proposed document, and exact operation before saving. Updates preserve `_id`; duplication creates a new ObjectId. The service reads the original in a snapshot transaction, checks that it is unchanged, performs one mutation, verifies exactly one affected document, and only then commits. Concurrent changes abort the operation. Ambiguous commits are not replayed. Editing requires MongoDB 4.2 or later with a transaction-capable replica set or sharded cluster; standalone servers remain usable for queries, acknowledged commands, and imports.
8. **MongoDB URI and cluster support.** Import `mongodb://` or `mongodb+srv://` connection strings. Host lists, authentication source, replica-set name, supported SCRAM mechanisms, explicit TLS options, and direct connections become separate profile fields. Passwords go to device Keychain when the profile is saved; the raw URI is not stored. SRV/TXT lookups use the device resolver, validate seed-domain restrictions, and discover members. Commands select the current primary and wait for elections within their timeout. Undelivered read results may restart after a primary-change response; writes and already-streaming exports are never replayed.
9. **Data import and full-query exports.** Import CSV or JSON with column/field mapping, value types, preview, destination confirmation, progress, and cancellation. SQL imports bind native values and use one transaction. MongoDB imports use acknowledged ordered batches; a failure or cancellation can leave completed batches and part of the current batch inserted. CSV/JSON exports stream query results independently of the 10,000-row display limit, while respecting the query's own filters and limits. Export uses a separate read-only connection, so console-only temporary tables and uncommitted changes are not available to that export connection.
10. **Interactive charts.** Tap chart points or use Inspect, filter a loaded result by date range, open the matching loaded rows or MongoDB documents, and export PNG or PDF. Drilldown is read-only and does not infer writable provenance. Charts use loaded results and show truncation; date filtering does not silently query the server. Saved charts continue to require an explicit Run action.

## SQL editor details

Selections, cursor positions, completion insertion, and error highlighting use UTF-16 offsets consistently with UIKit. Statement selection ignores semicolons inside protected literals and comments. Native bound parameters execute as the complete bound query rather than guessing which parameters belong to a fragment.

Format preserves quoted values, quoted identifiers, comments, PostgreSQL dollar quotes, and escape strings. Ambiguous MySQL backslash modes leave the input unchanged. Completion does not normalize unrelated whitespace. Command-Return runs the current selection or statement; Command-] and Command-[ change indentation. Syntax coloring preserves selection and avoids modifying IME composition.

All execution goes through `DatabaseService` and an explicit `DatabaseExecutionPolicy`. Explorer, charts, schema inspection, Explain, exports, and relationship navigation use read-only execution. Read-only SQL connections also configure a server-side read-only session. Row editing requires Explorer-generated single-table provenance and a usable identifier. Expected-count mutations validate the result inside a transaction before commit.

## MongoDB details

Find mode exposes collection, filter, projection, compound sort, skip, and limit. Aggregation mode exposes stage bodies with add, enable/disable, reorder, and delete actions. Both builders execute read-only, show the generated command, and support Explain, saving, and opening the generated command for editing. Command mode accepts one Extended JSON command, for example:

```json
{"find":"orders","filter":{"status":"open"},"sort":{"createdAt":-1},"limit":25}
```

Supported commands include find, aggregation, count, distinct, Explain, database/collection/index listing, collection/database statistics, ping, insert, update, delete, collection creation/drop, and index creation/drop. Command-mode writes require confirmation, including aggregation `$out` and `$merge`. Mongo shell JavaScript, X.509/OIDC/AWS authentication, load-balanced URIs, and secondary read preferences are not implemented. Unsupported URI options fail explicitly rather than changing their meaning.

MongoDB has no equivalent to SQL's read-only session flag. PortSQL enforces read-only policy on its commands; use server accounts with read-only roles when server-enforced protection is required. Document-edit controls are available only for full, unprojected Find results generated from the selected Explorer collection. Aggregations, arbitrary command results, projected documents, and chart drilldowns remain read-only in the document inspector. Insert explicitly targets the selected collection.

BSON and canonical Extended JSON preserve ObjectId, Decimal128, Int64, dates, binary subtype, null, arrays, and document key order. Missing fields remain distinct from null. Literal replacement prevents document fields such as `$set` from being interpreted as update operators. Ordinary commands are limited to 1 MiB and 100 nesting levels. The document editor accepts BSON documents up to MongoDB's 16 MiB document limit, allowing for a larger canonical JSON representation.

Materialized MongoDB results stop at 10,000 documents or 32 MiB and report truncation. The grid projects up to 256 columns, including nested scalar paths up to eight levels deep; original root keys take precedence over colliding dotted paths. The document inspector and JSON exports retain complete documents. Full-query exports stream cursor batches instead of accumulating all documents in memory. MongoDB CSV exports preserve typed field values as canonical Extended JSON; JSON is the clearest format for complete document interchange.

TLS uses system roots by default. Private CA adds roots without disabling hostname verification. Prefer TLS still requires TLS for MongoDB because its protocol cannot safely signal an unsupported-TLS downgrade. Plaintext remains an explicit warned choice. TLS over SSH validates the database member's original DNS hostname, and IP-only TLS identities through SSH remain blocked. Queries default to 30 seconds and clamp to 1–300 seconds; cancellation closes pending sockets and resolves outstanding replies. Transactional document saves require majority acknowledgement. Interrupted writes and uncertain commits must be checked on the server before retrying.

## Adaptive layout and release configuration

Explorer and Console use native navigation, safe areas, size classes, and available window dimensions. Narrow windows and accessibility text sizes stack the editor and results; sufficiently wide windows show them side by side. The layout does not hard-code device identities or orientation. Mac Catalyst is not supported.

Earlier development used `/Users/ieb/Applications/Xcode-27.1-beta.app` for Duo simulator work. Select experimental toolchains per command with `DEVELOPER_DIR`; do not change the system-wide Xcode selection. The 1.3.0 distribution must use a supported release toolchain. Width-adaptive layouts are included, but full Duo-specific iOS 27.1 SDK behavior, hardware operation, and manual fold/unfold verification are not release claims.

`project.yml` remains the XcodeGen source of truth and must stay aligned with `PortSQL.xcodeproj`. MongoClient and SwiftBSON are declared dependencies; DNSClient remains pinned to 2.6.0 for compatibility with the existing dependency graph. Native SRV/TXT discovery uses Apple's DNS service API through `libSystem`. Existing dependency pins and vendored MySQL transport/data fixes remain intact. The MySQL handshake retains the requested default database. Preserve the working-tree Release entitlement choice and transferred-app iCloud KVS ownership when generating or archiving.

Free supports three saved connections. Pro unlocks unlimited saved connections and premium line/area chart styles. Saved-query retention, recovery, and execution safety are not tied to the old library item caps.
